# Сверка макетов и вёрстки

Документ фиксирует, **что именно было в исходниках**, что с этим не так и по какому макету
свёрстан каждый экран. Нужен, чтобы при приёмке не возникало вопросов «а почему картинок 24,
а страниц 25» и «а почему оплата выглядит не как на картинке».

Служебная страница для сверки глазами: **`screens.html`** (открывается только по прямому URL,
из сайта нигде не слинкована, `noindex`).

---

## 1. Источник раскладки

| Что | Где | Статус |
|---|---|---|
| PSD-композиты (эталон) | `psd-extract/spec/<имя>/composite.png` | **25 шт., по одному на экран** |
| Тексты/шрифты из PSD | `psd-extract/spec/<имя>/texts.json` | 25 шт. |
| PNG-экспорты «для людей» | `01_исходники/макеты_png/` | **24 шт., часть — фрагменты и устаревшие версии** |
| PSD-файлы как таковые | `01_исходники/макеты_psd/` | **отсутствует, 0 файлов** |

**Правило приёмки: эталон — `composite.png`.** PNG-папка — вторична: там есть кропы без шапки
и подвала, полоса cookie высотой 305 px и один файл с неверным содержимым (см. п.2).

Все картинки для страницы сверки пережаты из composite до ширины 1400 px и лежат в
`02_верстка/assets/mockups/М01.jpg … М25.jpg` — то есть в наборе теперь **25 из 25**,
включая М18, у которого PNG-экспорта не было вообще.

## 2. Расхождения в папке `01_исходники/макеты_png` (по фактам)

### 2.1. «Выбор цвета и визуализатор.png» — не визуализатор (причина установлена по пикселям)

**Точная причина: файл экспортирован не из того PSD.** Сверка пиксель-в-пиксель
(допуск 12/255 на канал; у всех файлов 2560×1440):

| Сравнение | Результат |
|---|---|
| `Выбор цвета и визуализатор.png` ↔ composite PSD **«Список_оттенков»** | **0 отличий — идентичны** |
| `Выбор цвета и визуализатор.png` ↔ `Список оттенков.png` | 9 участков, 23 212 px = 0,63 % кадра |
| `Выбор цвета и визуализатор.png` ↔ composite **«Выбор_цвета_и_визуализатор»** | 1 782 451 px (bbox x 221…2559, y 0…1343) — другой экран |

Разница с `Список оттенков.png` — это только состояния одних и тех же элементов:
активная карточка №1 (бирюзовая рамка 2 px + галочка в круге) и кнопка «ЗАКАЗАТЬ ЗВОНОК»
в подвале в состоянии hover (область x 2128…2362, y 1362…1418). То есть в папке лежат
два кадра одной и той же страницы, а визуализатора среди них нет.

Структурное подтверждение из самих PSD (`tree.json`):

| Признак | PSD «Список_оттенков» | PSD «Выбор_цвета_и_визуализатор» |
|---|---|---|
| Слои интерьера («изображения большое», «изображения интерьеров внизу») | **0** | **15** |
| Слои-образцы `образцы_Группа_*` | **128** | **71** |
| Карточек в ряд в полосе y 320–480 | **8** (x 463, 649, 854, 1060…) | ~4 слева, справа интерьер (x 220, 301, 457, 984…) |
| Заголовок | «КОЛЕРОВКА ЦВЕТА» | «КОЛЕРОВКА ЦВЕТА / ACE PAINT» |

128 слоёв ÷ 8 на карточку = 16 карточек (8×2 ряда) — ровно то, что видно на PNG.
В PSD визуализатора слоёв образцов хватает на 6×3 = 18 слотов, а справа — интерьерная сцена.

> **Это расхождение заранее описано в самом ТЗ, п. 2.3:**
> «PNG из папки „изображения“ используются для просмотра, а PSD — как исходники для реализации.
> В частности, „Выбор цвета и визуализатор.png“ фактически показывает список оттенков и **не заменяет**
> М09 „Выбор цвета и визуализатор.psd“, содержащий товар, выбор цвета, интерьер, миниатюры сцен
> и действия покупки. Для М18 отдельного PNG в архиве нет; четыре сцены извлекаются из PSD».
> То есть подмена файла известна заказчику и зафиксирована в ТЗ — сверяться нужно по PSD.

**Статус на текущий момент:** правильный экран визуализатора добавлен в Figma
(скриншоты выгружались туда для удобства просмотра — у ПМ нет Photoshop). Папка
`01_исходники/макеты_png` остаётся вспомогательной: сверка ведётся по PSD.
Готовый текст для пересылки — `02_верстка/Пояснение_по_макетам_для_ПМ.md`.

**Вывод:** имя файла правильное, а содержимое — скриншот соседнего PSD. Оба документа лежат
рядом и называются похоже, поэтому при экспорте, скорее всего, открыли не тот (или переименовали
готовый файл «Список оттенков»). К вёрстке это отношения не имеет: `pages/visualizer.html`
собран по настоящему composite.

Настоящий макет визуализатора — `psd-extract/spec/Выбор_цвета_и_визуализатор/composite.png`:
слева карточка ACRILUX с «ВЫБЕРИТЕ ЦВЕТ» и каталогом ACE PAINT, справа интерьерная сцена (спальня),
ниже «Как это работает?», предупреждение о цветопередаче, цена «от 3 500 ₽» и кнопка «В корзину».

**Следствие:** `pages/visualizer.html` свёрстан по composite и совпадает с ним.
Ошибка была в экспорте PNG, а не в вёрстке.

### 2.2. «Заменяется безопасным сценарием оплаты.png» — это модалка, а не страница оплаты

Файл 1129×1060 содержит модальное окно «Реквизиты для оплаты»: поле **«Номер карты\*»**,
блок с иконкой щита и кнопки «СОХРАНИТЬ» / «ОТМЕНИТЬ». Шапки и подвала страницы нет.

**Уточнение (проверено по актуальной версии проекта).** Этот файл — единственный макет
М24, и он **реализован**: `pages/payment-card.html` повторяет его 1:1 — заголовок
«Реквизиты для оплаты», поле «Номер карты *» с иконкой, подсказка, блок с щитом
и кнопки «Сохранить» / «Отменить» + `js/payment-card.js` (маска и валидация).

Страница `pages/payment.html` — **другой экран**: выбор способа оплаты (картой онлайн / по счёту)
с уведомлением о безопасной оплате на стороне банка. Своего макета в исходниках она не имеет
и собрана по тексту ТЗ (п. 8.3). То есть в проекте два экрана оплаты: витрина способов и форма
реквизитов, и оба соответствуют своим источникам.

Фрагменты свёрстаны как модальные окна — это нормально, страницы у них нет по определению.

Это не экран, а набор изображений: `assets/img/viz-hero.png` (спальня 1337×722) и
`viz-thumb1…3.png`. Используются на странице визуализатора (М09), отдельного URL не имеют.

## 4. Как сверять

1. Открыть `screens.html` (только по прямому URL: `…/screens.html`).
2. Слева — макет, справа — код, название и кнопка «Открыть страницу».
3. Макеты нарисованы под ширину 2560 px. Чтобы сравнение было честным, смотрите вёрстку
   на мониторе 2560 px либо уменьшите масштаб браузера так, чтобы ширина страницы совпала
   с шириной картинки.
4. Адаптив (1920 / 1440 / 1280 / 1024 / 768 / 540 / 360) с макетами не сверяется — макеты
   нарисованы только под десктоп; правила адаптива описаны в `ADAPTIVE.md`.
